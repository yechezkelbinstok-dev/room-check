# Room Check sync

The app and the website each keep their own copy of every night and work with no signal at all.
This little server is what lets those copies find each other, so a check marked on the website
shows up on the phone and the other way round.

It stores nights and nothing else — no accounts, no roster, no names beyond what is in a night.

**It costs nothing.** Cloudflare's free tier covers this many times over: a night is a few kilobytes
and there are a few hundred a year.

---

## Setting it up from a phone

No computer, no command line. Everything below is in a browser at **dash.cloudflare.com**.

Cloudflare moves its menus around, so these are the four things that need to exist rather than an
exact set of taps. If a name has changed, look for the nearest thing to it.

**1. Make an account.** Free. Email and a password.

**2. Make the storage.** Find **Storage & Databases → KV**, create a namespace, call it
`room-check`. (Older dashboards put KV under *Workers & Pages*.)

**3. Make the Worker.** **Compute → Workers**, create one from the Hello World starter, name it
`room-check-sync`. Open its editor, delete everything in the file, and paste the whole of
[`worker.single.js`](worker.single.js). Deploy.

That file is one self-contained piece on purpose — pasting into a browser editor has no way to
fetch a second file.

**4. Wire the two together.** In the Worker's **Settings → Bindings**:

- Add a **KV namespace** binding. Variable name **`NIGHTS`** — spelled exactly that, the code
  looks for it by name. Point it at the `room-check` namespace.
- Add a **Secret** called **`SYNC_TOKEN`**. Its value is a sync password you invent — long, not one
  you use anywhere else. You will type it into the app once.

Deploy again after adding those.

The Worker's page shows its address, something like
`https://room-check-sync.<your-name>.workers.dev`.

---

## Pointing the app and the site at it

In **Settings → Sync**, on both the app and the website:

- **Server address** — that URL
- **Sync password** — the `SYNC_TOKEN` you invented

Then **Sync now**. After that it looks after itself: when the app is opened, when the website tab
comes back to the front, and a few seconds after marking stops.

Leave the address blank and nothing changes — each device keeps to itself, exactly as before.

## If it does not work

The line under **Sync now** says what happened rather than failing quietly.

- *Wrong sync password* — the app's password and the Worker's `SYNC_TOKEN` are not the same.
- *Server said 500* — the `NIGHTS` binding is missing or spelled differently.
- *Could not reach the server* — the address is wrong, or the Worker was never deployed.

## From a computer, if you have one

```sh
npm install -g wrangler
wrangler login
wrangler kv namespace create NIGHTS     # prints an id; put it in wrangler.toml
wrangler secret put SYNC_TOKEN
wrangler deploy
```

## How conflicts are settled

Not by last-save-wins. That would mean two people walking different rooms at the same time, each
saving a full night, and whoever saved second erasing the other's rooms.

Instead every night carries a timestamp per *cell* — one mark, one note, one excusal — and merging
happens cell by cell: the later edit of each individual cell wins, and cells nobody touched are
left alone. Marking Room 1 on the phone while someone marks Room 5 on the website leaves both.

That rule is written three times — `android/.../Merge.kt`, `merge.js`, and inside `index.html` —
because the three run in different places. All three are pinned to the same cases in
`fixtures.json`, so the copies cannot quietly drift into disagreeing.

```sh
npm test    # the shared cases, the server, and the pasteable single-file copy of it
```

`worker.single.js` is generated by `npm run build` from `worker.js` + `merge.js`, and the tests run
against the generated file too — so what gets pasted is what was tested.

## A note on what is exposed

Anyone with the URL *and* the password can read and write the sheet. That is the whole security
model — deliberately the same shape as the site's own password. Use a password you would not mind
being the only thing between the internet and the sheet, and don't reuse one.
